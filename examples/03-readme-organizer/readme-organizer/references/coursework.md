# Template: Coursework

A visitor (often a recruiter or a future you) wants to know: what was built, what you learned, and how to run it.

## Before writing: check academic integrity

Many courses forbid publishing solutions publicly. If this repo is (or will be) public and contains assignment solutions, **warn the user before writing anything**: suggest checking the course policy, and offer to make the README describe the work without exposing solution code. Continue only after they confirm.

## Skeleton

````markdown
# Project Title

One sentence: what it does, plus the course it was built for (e.g. "Final project for 15-112 at Carnegie Mellon University, Fall 2026").

![Screenshot](docs/screenshot.png)   <!-- if visual -->

## What it does

A short paragraph on the problem or assignment in your own words. Don't paste the handout.

- What you built or implemented
- Interesting technical piece (algorithm, data structure, design choice)
- What you learned or found challenging   <!-- optional, valuable for portfolios -->

## Installation

Requirements: Python 3.x (and libraries, e.g. cmu_graphics)

```bash
git clone https://github.com/user/repo.git
cd repo
pip install -r requirements.txt
```

## Usage

```bash
python main.py
```

Describe what happens or what to try. For multi-part assignments, list each part with its run command.

## Acknowledgments   <!-- course, instructors, starter code provenance -->
````

## Type-specific notes

- **Starter code:** if parts of the repo came from course staff (handout files, autograders), say so in Acknowledgments so it is clear what is the user's own work.
- **Don't include** handout PDFs' text, grading rubrics, or test-case answers in the README.
- **If the project is also a game, web app, etc.,** borrow that template's type-specific sections (Controls, Live demo) and keep the course line and Acknowledgments from this one.
- Phrase it as a portfolio piece: emphasize what was built and the decisions made.
